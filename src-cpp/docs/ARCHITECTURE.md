# C++統計分析エンジンの構成方針

## 目的と位置づけ

`src-cpp/` は、SAIの統計分析と派生変数の計算を担う独立したC++ライブラリを置くディレクトリです。GUIに依存せず、デスクトップアプリや他の呼び出し元から共通の分析・変数変換機能を利用できることを目指します。

C++を本番の分析エンジンとし、Rは試作や参照値の生成に利用します。SPSSの公開アルゴリズムや論文の計算例も、仕様を検討し、数値結果を検証するための参照として扱います。分析名が同じという理由だけで、各ソフトウェアの結果が一致すると仮定しません。

この文書は設計方針と拡張先を示すものであり、記載したディレクトリや機能がすべて実装済みであることを意味しません。必要な機能から段階的に追加します。

## アプリケーションとの境界

既存の分析処理は、TypeScriptの画面からRustの `AnalysisService` を経由し、`RRunner` でRを呼び出す構成です。C++エンジンは独立したRustクレート `crates/sai-engine/` から呼び出すライブラリとして組み込みます。アプリケーション層は当面 `src-tauri/` に残します。全体の配置と移行手順は [RからC++への移行計画](../../docs/CPP_ENGINE_MIGRATION.md) を参照してください。

```text
TypeScriptのGUI
    ↓
Rust：外部入力の解析・型変換・変数の解決
    ↓
型付きの列データ・欠損情報・分析または変数変換の設定
    ↓
crates/sai-engine/：安全なRust API・メモリ管理・C互換接続
    ↓
C互換アダプター → C++の公開分析・変数変換API
    ↓
C++：分析・変数変換の検証・前処理・計算
```

Rustは外部データを解析し、型付きの入力へ変換します。C++はその入力の統計的な意味を検証し、前処理と計算を行い、推定値、検定結果、使用件数、診断情報などを返します。ここでいう「構造化された入力」は、数値配列、カテゴリコード、欠損マスク、列の役割、型の決まった分析設定などです。JSONやRustの構造体をそのままC++へ渡す意味ではありません。

表示桁数、日本語の表見出し、画面構成、分析履歴の保存はアプリケーション側で扱います。検出力分析の結果を分析ログへ保存しない現行仕様も、この構成によって変更しません。

CSV・Excel・SPSSファイルの読み込みは既存のアプリケーション側の入口を利用し、初期段階ではC++に汎用の `io/` を設けません。将来必要になった場合も、ファイル形式の処理を統計計算から分離します。

### RustとC++の責務

分析に使う値と統計結果を決める処理はC++、外部表現の変換、データの保存・更新、表示との接続はRustが担当します。表示用の丸めや画面座標などの計算はアプリケーション側に置きます。

| 処理 | 主な担当 | 境界の考え方 |
| --- | --- | --- |
| ファイル読み込み・JSON解析 | Rust | アプリケーションの入出力として扱う |
| 文字列の数値化・変数名の解決 | Rust | 変換規則を明示し、元の行・列との対応を維持する |
| カテゴリラベルの整数コード化 | Rust | 水準の対応と順序を保持し、統計上のコントラストを作らない |
| GUIで選択した分析条件の型変換 | Rust | 未知の指定を拒否し、選択された意味を保持する |
| 配列長・行列サイズ・列参照の整合性確認 | RustとC++の入口 | 各入口で受け付ける入力の契約を確認する |
| 必要な標本数・設定の組み合わせ・値域の検証 | C++ | 分析手法として成立するかを判断する |
| 欠損処理の適用・分析対象行の決定 | C++ | 手法と指定された欠損処理に従う |
| 設計行列・ダミー変数・コントラストの生成 | C++ | モデルの指定に従い、結果に影響する規則を集約する |
| 推定・検定・収束判定 | C++ | 共通の統計仕様で実行する |
| 逆転・合計得点・標準化・再コード化 | C++ | 派生列の値を計算し、変換設定と値域・欠損の扱いを検証する |
| 新しい列名の衝突確認・データセットへの登録 | Rust | 全列の成功後にまとめて更新し、同時更新とキャッシュを管理する |
| 結果のJSON化・診断情報の表示 | RustとGUI | 数値や診断の意味を保持して表示へ変換する |

Rust側でGUI向けの事前チェックを行っても、C++の公開APIに必要な検証は省略しません。別の呼び出し元から利用しても、同じ分析仕様が適用される必要があります。統計的な判定の本体はC++に置き、Rustに独立した判定ロジックを増やしません。

たとえば回帰分析では、Rustが目的変数と説明変数を解決し、数値列・カテゴリ列・欠損情報・モデル設定を渡します。C++が指定された欠損処理を適用し、切片やコントラストを含む設計行列を作成して推定します。カテゴリコードそのものを連続量やダミー変数として解釈しません。

### 入力契約

公開APIは分析ごとに必要な型付き入力を受け取ります。すべての分析を単一の汎用JSONや数値行列に押し込めません。生データ、距離行列、検出力分析のパラメーターなどは、入力の種類を区別します。

- 数値列は値と欠損マスクを持ち、欠損と無効な数値を混同しない。NaNや無限大の許容条件は手法の仕様で定義する。
- カテゴリ列はコードと水準の対応・順序を保持する。参照水準やコントラストは分析設定としてC++へ渡す。
- 列の役割、行列のサイズ・配置、元の行・列との対応を明示する。行列入力では行と列の対応を保つ。
- 設定値の省略と不正な値を区別する。統計上の既定値はC++側の仕様で定義・適用し、適用済み設定を結果に含める。Rustが独自の既定値へ置き換えない。

Rustでの数値変換に失敗した値を、無条件に欠損として扱いません。原則として行・列を特定できるエラーにし、欠損扱いを許可する明示的な入力規則がある場合だけ、その規則を適用して件数と理由を通知します。ファイルに記録された欠損値の定義も入力情報として保持し、分析に適用する扱いが選択可能な場合は設定として渡します。

利用者が明示した変数変換は、C++が派生列を計算し、Rustがデータセットへ登録します。変換に使うデータ範囲の選択は明示的な要求として渡します。この操作と、C++が分析のために適用する欠損処理・前処理を区別し、どの段階で対象データが変わったかを追えるようにします。

### 結果と診断情報の契約

C++は計算結果に加えて、実際に適用した設定、使用件数、除外情報、警告、推定不能・未収束の状態を返します。診断はコードと対象・件数などの構造化された情報を持たせ、GUIが表示文へ変換できるようにします。

Rustは入力変換時の診断とC++の分析診断を呼び出し元へ伝えます。両者の件数が何を数えているかを区別し、除外件数を二重に加算しません。未定義の結果をゼロへ置き換えたり、警告を落としたりしません。

## モジュールの責務と依存方向

### 公開API：`include/sai/`

呼び出し元が必要とする入力、オプション、結果、診断情報、分析関数を定義します。手法固有のオプションと結果は、その手法のヘッダーにまとめます。

Eigenなどの具体的なライブラリ型は原則として公開APIに露出させません。入力を参照で受け取る場合は、有効期間やデータ配置の条件を公開APIで明記します。

### 分析手法：`src/analysis/`

利用者が選ぶ分析の単位です。手法固有の入力検証、設定の解釈、計算の組み立て、分析結果の構築を担当します。

たとえば回帰分析は係数や適合度を返し、ANOVAは平方和やF検定の結果を返します。平方和Type I／II／IIIなどの統計上の選択は、ANOVAの明示的な設定として扱います。

### 共通モデル：`src/models/`

複数の分析から再利用するモデル計算を置きます。回帰とANOVAは、必要に応じて同じ `models/linear/` を使います。最小二乗推定やランク判定を、それぞれの分析で重複実装しないための境界です。

`design_matrix/` は切片、カテゴリ変数のコントラスト、交互作用など、モデルの指定から設計行列を構成する処理を担当します。外部ラベルからカテゴリコードへの変換はRust、受け取ったコードを使う群分けや対象行の抽出は `data/`、モデルに必要な符号化は `design_matrix/` の責務です。

### 変数変換：`include/sai/transform/` と `src/transform/`

逆転項目、合計得点、標準化、再コード化など、分析に使う新しい変数の値を計算します。最初は逆転項目を実装し、他の変換は必要になった段階で追加します。公開APIは型付きの元データと変換設定を受け取り、派生列、欠損情報、適用設定、診断情報を返します。アプリケーションが保持するデータセットを直接変更しません。

変数変換の結果は、分析結果の表とは別の契約です。逆転項目では元と同じ行数・行順を保ち、欠損行を削除しません。尺度の上下限と範囲外の値をC++で検証し、範囲外の値を黙って補正しません。合計得点の一部欠損の許容条件、標準化の基準となる観測範囲や分散の定義、再コード化の未一致値の扱いも、各変換の設定・仕様で明示します。

Rustは元の変数を解決して入力を渡し、戻った列の長さと対応を確認して、指定された新しい列名で登録します。列名の衝突確認、複数列の原子的な追加、同時更新、キャッシュの無効化はRustの責務です。計算式と変換固有の判定をRustに重複実装しません。

### 数値計算と確率分布

`numerical/` は、特定の分析手法に依存しない計算を担当します。`distributions/` は、検定や信頼区間で使う確率・分位点などを提供します。

EigenやBLAS／LAPACKは内部実装の候補です。巨大な独自行列ライブラリを作るのではなく、SAIで共通化する必要がある操作や数値的な判定をまとめます。特殊関数や確率分布も、すべてを自前実装する前提にはしません。

### 依存の原則

- アダプターは公開APIを呼び、内部実装へ直接依存しない。
- 分析手法はモデル、データ処理、確率分布、数値計算を利用できる。
- 変数変換は共通のデータ処理や数値計算を利用できる。分析と変数変換で共有する計算は下位モジュールへ置き、互いの公開手順へ依存させない。
- モデルはデータ処理や数値計算を利用できるが、分析手法へ依存しない。
- 共通基盤はGUI、Rust、JSON、アダプターへ依存しない。
- 他の分析と共通化する計算は、分析同士を相互依存させず、適切な下位モジュールへ置く。

## 欠損値・設定・診断情報

欠損値処理の「実行する仕組み」と「どの処理を選ぶか」を分離します。`data/` は行の除外や有効なペアの抽出を提供し、各分析のオプションが適用する処理を決めます。全分析の前に一律のリストワイズ削除を行う構成にはしません。

不正な設定値を受け取った場合はエラーにします。無効な相関の欠損処理設定を別の方式に置き換えるなど、利用者が意図しない分析結果の変更は禁止です。省略可能な設定に既定値を設ける場合は、その値を仕様に記載し、実際に適用した設定を結果から確認できるようにします。

結果には、分析に適した粒度で使用件数・除外件数・適用設定を含めます。ペアワイズ相関など、計算ごとに対象件数が違う場合は、単一の件数へまとめません。

ランク不足、収束しなかった計算、推定不能な値などは診断情報で表現します。失敗や未定義の値を正常な数値に見せかけず、呼び出し元が利用者へ伝えられる形にします。

## 外部接続：`adapters/`

初期のRust接続には `adapters/c_api/` のC互換APIを使う方針です。Rust側の安全なラッパー、エンジンの入出力型、C互換表現への変換は `crates/sai-engine/` に配置します。生のFFIは同クレート内部に閉じ込めます。C++側のアダプターはC互換表現と公開C++型の変換、エラーの受け渡しを担当し、統計上の規則を実装しません。

依存方向は `src-tauri → sai-engine → C++` とします。`sai-engine` はTauri、JSONのIPC形式、データセット管理、履歴、表示言語に依存しません。外部入力の数値化・変数名の解決と、結果のアプリ用DTOへの変換は `src-tauri/` が担当します。アプリケーション層の独立クレート化は将来の共有要件に応じて判断し、今回の移行では行いません。

C互換の境界では、入力・出力のメモリ所有権、有効期間、解放方法を定義します。Rustの構造体やC++の標準コンテナーの内部表現をそのまま共有せず、ポインターと要素数、固定した表現の設定値などで契約を定めます。C++例外は境界内で処理し、呼び出し元が解釈できるエラーへ変換します。

初期APIは同期呼び出しとし、入力バッファは呼び出し中だけ借用します。Rust側が有効期間を保証し、C++は入力を書き換えず、戻った後に参照を保持しません。返却データは所有権と専用の解放手順を定め、確保した側で解放します。非同期化やデータ保持が必要になった場合は、この契約を明示的に拡張します。

アダプターは長さ・サイズの整合性、必須ポインターのnull、設定値の表現などを確認します。ただし、任意の非nullポインターの有効性を検査できるわけではないため、Rust側ラッパーにも安全なバッファを渡す責任があります。

不要なコピーは避けますが、最初から完全なゼロコピーを要件にしません。欠損行の抽出、設計行列の生成、分解用の作業領域などに必要なコピーはC++で行います。データ配置と実測に基づいて最適化します。

SAIのJSON解析・シリアライズはRustに置き、C++の接続には使いません。将来、独立したJSON接続が必要になった場合は専用アダプターとして追加し、統計計算から分離します。

## 検証と仕様の記録

### 参照値の生成とテストを分ける

`validation/` はRやSPSS、公開計算例を使って参照値を生成・確認するための場所です。`tests/fixtures/` に入力と期待値を保存し、`tests/reference/` でC++の結果と照合します。

通常のC++テストは保存済みの期待値を使い、RやSPSSの実行環境を必須にしません。参照値を再生成するときは、生成環境と数値差を確認します。実装に合わせる目的だけで期待値を上書きしません。

各検証ケースには、少なくとも次を記録します。

- 入力データと分析オプション。
- 期待値の出典、参照ソフトとパッケージのバージョン。
- 欠損値処理、自由度補正など結果に影響する計算条件。
- 再生成の手順と、比較に用いる絶対誤差・相対誤差などの許容条件。

### 一致させる仕様を先に決める

RやSPSSを無条件の正解とは扱いません。平方和、標準誤差、タイの扱い、因子抽出・回転、収束判定などの条件を揃えて比較します。結果が異なる場合は原因を調べ、採用する仕様と既知の差異を `docs/methods/` に記録します。

数値の比較方法も対象に合わせます。たとえば因子負荷量などは、符号や並び方の違いを考慮する必要があります。比較のための調整は検証側に明記し、本番結果を黙って変更しません。

`tests/unit/` では境界条件や入力検証、数理的な性質も確認します。`tests/integration/` は公開APIと外部接続の契約を確認し、`benchmarks/` は正しさのテストと分けて性能を測定します。

Rust側のテストでは数値変換、カテゴリ水準の保持、変数の解決、入力診断の伝達を確認します。C++側では型付き入力の整合性、欠損処理、モデル構築、分析設定の検証を確認します。RustからC互換APIを通す結合テストでは、行・列の対応、結果・警告の受け渡し、メモリの解放まで確認します。これらは各実装の追加時に用意します。

RustとC++の接続テストは `crates/sai-engine/tests/` に置き、Tauriなしで実行します。アプリケーションの入力変換、データ更新、IPCへの接続は `src-tauri/` のテストとして分けます。

変数変換では、値の計算、尺度範囲、欠損と行対応の保持をC++で検証します。Rustでは列名の衝突、変換失敗時に列が追加されないこと、同時更新とキャッシュ無効化を確認します。接続テストでは派生列と診断が登録・表示まで届くことを確認します。

## 段階的な実装と配置の判断

最初は次の順序で、RustからC++まで実際に呼べる最小の経路を作ります。

1. 数値列・欠損情報・設定・結果・診断情報の契約と、メモリ所有権を定義し、`crates/sai-engine/` に独立したRust APIとビルド連携を用意する。
2. 記述統計を実装し、Rustの入力変換、C互換API、結果の受け渡しまで接続する。
3. Welchのt検定と必要な確率分布、参照テストを追加し、欠損処理や不正な入力の扱いを確認する。
4. カテゴリ列とモデル設定の契約を具体化し、回帰とANOVAで共有するモデル基盤へ進む。

基本の接続ができた段階で、逆転項目の変数変換APIも実装し、Rustのデータセット更新まで接続します。分析APIの進捗とは別に、変数作成のR依存を解消します。

RからC++への移行は手法単位で行います。C++で失敗した分析を自動的にRでやり直すなど、結果の計算経路を黙って切り替える処理は設けません。

新しい処理の配置に迷った場合は、次の基準で判断します。

| 処理 | 配置先 |
| --- | --- |
| 外部から使う分析関数・オプション・結果の宣言 | `include/sai/analysis/` |
| 特定の分析手法の手順・結果構築 | `src/analysis/` |
| 変数変換の入力・設定・派生列の結果の宣言 | `include/sai/transform/` |
| 逆転・合計得点・標準化・再コード化の計算 | `src/transform/` |
| 複数の分析で共有するモデル推定 | `src/models/` |
| 欠損の抽出・群分けなどのデータ処理 | `src/data/` |
| 統計手法に依存しない数値演算 | `src/numerical/` |
| 確率分布に関する計算 | `src/distributions/` |
| C互換表現と公開C++型の変換 | `adapters/c_api/` |
| ファイル・JSON解析、文字列の数値化、変数名の解決 | `src-tauri/`（`src-cpp/` の外） |
| Rust側の安全な呼び出しラッパー・エンジンの入出力型・C++ビルド連携 | `crates/sai-engine/`（`src-cpp/` の外） |
| アプリ用DTOへの変換・結果のJSON化 | `src-tauri/`（`src-cpp/` の外） |
| 列名の検証・派生列の登録・キャッシュ更新 | `src-tauri/`（`src-cpp/` の外） |
| 参照値を生成するスクリプト・手順 | `validation/` |
| 保存済みの期待値と比較するテスト | `tests/reference/` |
| 手法の計算条件・参考文献・互換性の説明 | `docs/methods/` |

ディレクトリを埋めるために抽象化を増やさず、実際に共有する責務が生まれた段階で分離します。公開APIや計算仕様を変更したときは、対応する仕様文書と検証ケースも更新します。
